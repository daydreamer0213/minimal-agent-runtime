# Minimal Agent 真实网页录屏设计

日期：2026-07-29

## 1. 目标

用真正的连续网页操作录屏替换当前的“截图转场版” `artifacts/demo.mp4`。

新版必须让观看者清楚看到：

- 鼠标点击、输入文字、发送请求和等待 Agent 返回的连续过程。
- DeepSeek 自主决定调用天气、待办等工具。
- 同一个 Session 能继续追问并读取历史状态。
- 两个 Session 的聊天、待办和 Trace 彼此隔离。
- 右侧 Trace 能看到 `MODEL → TOOL → RESULT → ANSWER` 的执行过程。

## 2. 录制方式

采用真实 Edge 窗口录制：

- 用本地网页入口运行现有 `AgentRuntime`，不制作假的前端动画。
- 使用单独的录屏数据库，避免污染日常演示数据。
- 录制指定浏览器窗口，不录入 Codex、终端或桌面上的其他内容。
- 以 30 FPS 连续捕获画面，并保留鼠标指针。
- 使用现有 `.env` 调用真实 DeepSeek API，但画面中不打开或显示 `.env`。
- 预计发送 2～3 次用户请求；模型等待过长的部分允许剪短。

当前截图转场版保留在 Git 历史中，新版验收通过后覆盖同一路径。

## 3. 录制脚本

录制顺序如下：

1. 打开 Minimal Agent 网页，停留约 2 秒，让评审看清整体布局。
2. 创建 `weather-demo` Session。
3. 输入“查询杭州明天天气，并提醒我带雨伞”，点击发送。
4. 等待真实 Agent 完成天气查询和待办创建，展示回答、Trace 和待办。
5. 输入“列出这个会话当前的待办”，展示带工具的追问。
6. 创建 `weekly-demo` Session。
7. 输入一条周报请求，并要求创建“检查周报”待办。
8. 展示周报回答、Trace 和该 Session 的待办。
9. 在两个 Session 之间切换，证明聊天、待办和 Trace 没有混在一起。
10. 停留在能够同时看见回答、Trace 和待办的画面后结束。

## 4. 剪辑原则

- 成片目标时长为 60～100 秒。
- 保留真实点击和输入，不使用截图缩放、幻灯片转场或模拟聊天结果。
- 只允许剪掉模型长时间等待和录制前后的无关画面。
- 可以加入不超过 2 秒的简单标题，但不能遮住主要操作。
- 默认无配音；网页内容和操作过程本身应足以说明功能。
- 输出格式为 H.264 MP4、1280×720、`yuv420p`，确保常见播放器可打开。

## 5. 异常处理

- 如果某次真实 API 请求失败，停止本次录制并检查页面错误，不把失败画面混入成片。
- 如果模型没有按预期调用工具，删除本次专用录屏数据库并重新录制该场景。
- 如果窗口尺寸或鼠标位置不正确，先停止录制，再重新校准；不在错误画面上继续操作。
- 如果录屏工具无法只捕获指定窗口，先验证不会录入隐私内容，再考虑使用固定区域捕获。

## 6. 验收标准

- 视频是连续录制画面，肉眼能看到鼠标、输入和页面状态变化。
- 至少出现一次真实天气工具调用和一次真实待办工具调用。
- 至少出现一次带历史上下文的追问。
- 能明确看到两个 Session 的数据隔离。
- 视频中没有 API Key、`.env` 内容、终端隐私或 Codex 操作界面。
- 视频可从头到尾完整解码。
- 视频分辨率、编码、像素格式、时长符合第 4 节要求。
- 从开头、中间和结尾抽帧检查时，文字清晰、窗口没有被遮挡。
